# The Two-Designer Agency: Building a World-Class In-House Design Org at Auterion with AI Agents (May 2026)

## TL;DR
- **You can credibly run agency-grade brand, design system, UX, and design ops with two humans plus an agent bench** — but only if you pick the right stack and accept hard tradeoffs around defense compliance. Your operating leverage comes from three moves: (1) treat your design system as the contract that constrains every AI agent's output (Figma Variables → Code Connect → Figma MCP), (2) standardize on Claude as the orchestrator with specialized skills/plugins for design work, and (3) split your tool stack into a "commercial side" (marketing, brand, public web) and a "regulated side" (Dragon, Auterion Mission Control, anything touching ITAR/EAR data) with strict, documented data boundaries.
- **The Pencil + Magic Path + Claude Code + Figma MCP loop is the most defensible AI design workflow in 2026** for product UX work. Pencil's six-agent swarm gives you parallel divergent exploration, Magic Path imports your Figma tokens and live URLs for code-grade iteration, Figma remains your design system source of truth, and Claude Code (with Figma MCP + Code Connect + custom skills) closes the loop into your codebase. Webflow handles the brand/marketing site; Jira + Rovo handles design intake/triage; Linear is the better choice if you can move your team off Jira.
- **Defense-specific reality check:** Defense Secretary Pete Hegseth designated Anthropic a "supply-chain risk to national security" on February 27, 2026, blocking commercial activity with the company for DoD contractors during a six-month wind-down. For Auterion's Dragon and any AMC work touching ITAR technical data, you need a parallel "regulated lane" using Claude through AWS Bedrock GovCloud (FedRAMP High, IL5) or Microsoft 365 Copilot in GCC-High (generally available December 2, 2025, adhering to FedRAMP High, DFARS, ITAR, and CMMC), plus an air-gapped design alternative like self-hosted Penpot for any sensitive UI surface that cannot leave your boundary. The cloud Figma file containing your tactical UI is the single biggest compliance risk in a "modern design stack" — solve it explicitly, not by hope.

## Key Findings

1. **Design system is not a deliverable, it's the harness for every agent.** Sen Lin's writeup in UX Collective (May 2026) makes the point bluntly: Claude Code knows how to call Figma APIs and bind variables — it just doesn't know that in your project, it *must*. Without an enforcement layer (Code Connect mappings + a token map + a component registry + Claude Skills that gate construction), every agent will silently invent its own values and your "two-designer agency" will produce inconsistent output at scale. This is the single highest-leverage investment you can make in Q1.
2. **The Figma MCP + Code Connect combination is the closest thing to a real "design-to-code" pipeline that exists in 2026** — but it requires CLI-level Code Connect mappings on your most-used components to be worth it. Without Code Connect, the Figma MCP server returns generic React/Tailwind; with it, agents get import paths, prop mappings, and example code from your real codebase. Figma now has a Claude Code plugin that installs MCP + agent skills with `claude plugin install figma@claude-plugins-official`.
3. **Pencil and Magic Path solve different problems and you should use both.** Pencil (pencil.dev / usepencil.design) embeds a vector design canvas directly in your IDE alongside Claude Code, treats designs as code (`.pen` files = JSON), and supports a 6-agent swarm mode for parallel divergent exploration — the killer feature for a 2-person team that can't otherwise afford to explore 6 directions per screen. Pencil CEO Tom Krcha (interview with Creator Economy's Tom Krcha) recommends Claude 4.6 as the model to attach in swarm mode. Magic Path (magicpath.ai) is an infinite-canvas tool for ideation, with three entry points (prompt-to-UI, Figma import, live-site web capture) all outputting clean React/Tailwind. Magic Path is better for early ideation; Pencil is better for sustained iteration tied to a real codebase.
4. **Claude is the orchestration substrate, not "an AI."** The Anthropic skills repository (github.com/anthropics/skills) ships official `frontend-design` and `brand-guidelines` skills; the broader ecosystem (Owl-Listener's 63 design skills, Design System Ops's 21 design-system practitioner skills, Antigravity Awesome Skills' 1,234+ skills with 22,034 GitHub stars) means you can compose specialized agents (UX research, accessibility, design QA, handoff, token audits) inside one Claude Code session. Claude Design (Anthropic Labs, launched Nov 2025) lets non-designers produce on-brand artifacts with your team's design system applied automatically — useful for stakeholder mockups but a compliance landmine for regulated work.
5. **Jira Rovo agents are good enough to delegate design intake and triage** to. Atlassian's "agents in Jira" (open beta as of late 2025/early 2026) plus Rovo Studio let you build no-code agents that auto-triage incoming design requests, summarize stakeholder threads, generate PRDs in Confluence, and route to the right designer. Per Atlassian's Team '25 blog, "Nearly 2,000 Rovo Agents have already been integrated into customer workflows" (with around 20 prebuilt out-of-box agents to start from). If your org is Jira-native, this is your "third designer" for ops work. If you have flexibility, Linear Agent (launched March 26, 2026, with MCP support added April 23, 2026 per Linear's official changelog) is more elegant — but Atlassian is the safer bet inside a defense org where ITAR compliance and on-prem options matter.
6. **Webflow is the right choice for auterion.com and marketing pages.** Webflow's AI Assistant, AI code components (React-backed), and the Webflow MCP server (connects Webflow to Cursor/Claude/Windsurf for CMS and SEO automation) let two designers operate a marketing site at agency scale. Webflow Optimize and AEO (Answer Engine Optimization) are genuinely novel and matter for defense-tech inbound, where buyers research via AI search.
7. **Anthropic's DoW designation (Feb 27, 2026) materially changes the math** for any Auterion work touching covered DoD contracts. The Pentagon's "supply chain risk" label means defense contractors cannot use Claude in performance of covered DoW contracts during the six-month wind-down. On March 26, 2026, US District Judge Rita Lin (N.D. Cal.) issued a sweeping preliminary injunction covering all 17 federal agencies named as defendants — per CNN, the order stated: "Nothing in the governing statute supports the Orwellian notion that an American company may be branded a potential adversary and saboteur of the U.S. for expressing disagreement with the government." Despite that injunction, the D.C. Circuit denied Anthropic's stay request on the FASCSA designation. The practical answer is: route any regulated work through Bedrock GovCloud (FedRAMP High + IL5 + ITAR) or use Microsoft 365 Copilot in GCC-High (generally available Dec 2, 2025 per techcommunity.microsoft.com, aligned to FedRAMP High, DFARS, ITAR, and CMMC, with no DoW restriction).
8. **Anduril's design org has 50 designers and uses Figma with a proprietary "Matter" design system.** Per Fast Company's Mark Wilson, who was "the first journalist to be invited inside" Anduril's design lab: "Bucci's team of 50 designers help craft the look and feel of Anduril's offerings, from the shape of the weapons to the way they're marketed." Anduril's job listings for the Design Systems team confirm "Matter" by name and require "deep expertise in Figma (libraries, variables, component architecture, branching)" — meaning cloud Figma is operationally tolerable inside defense contractors if you scope what touches it. Anduril's brand (Helvetica Now, monochrome with a single safety-yellow accent, Tolkien mythos) is a useful comparison point: it competes on confidence, simplicity, and craft, not on more "tech blue." Helsing, Palantir, and Skydio play in adjacent territory with similarly disciplined identity systems. Your brand opportunity at Auterion is to occupy that same register — disciplined, technical, and intentional — and not drift into either "consumer SaaS" or "primes contractor PowerPoint."

## Details

### Section 1 — The Agent Stack: orchestration, roles, handoffs

Think of your agent bench as four layers, not a single "AI tool list":

**Layer 1 — Orchestrator (one tool):** Claude Code is the right default. It runs in your terminal, has first-class Figma MCP support (install via `claude plugin install figma@claude-plugins-official`), accepts custom skills as Markdown files in `~/.claude/skills/`, and has the strongest taste for front-end work of any current model per Anthropic's own `frontend-design` skill documentation, which explicitly instructs the model to avoid: "generic AI-generated aesthetics like overused font families (Inter, Roboto, Arial, system fonts), cliched color schemes (particularly purple gradients on white backgrounds), predictable layouts and component patterns, and cookie-cutter design that lacks context-specific character." For non-Claude-Code work, Claude.ai with the Figma, Jira, Slack, Drive, and Webflow connectors covers the chat-style "design partner" use case.

**Layer 2 — Specialized agents (a small bench of skills + plugins):**
- **Frontend design / aesthetic direction:** Anthropic's official `frontend-design` skill from github.com/anthropics/skills (install `npx skills add anthropics/skills --skill frontend-design`). This is the single highest-leverage skill to install — it forces Claude to commit to a deliberate aesthetic direction before writing any code.
- **Design system enforcement:** Sen Lin's four-skill harness (Preflight, Brief Parser, Library-First Construction, Code Mode) published in UX Collective is the best public template; Design System Ops (designsystemops.com, MIT, 21 skills) is the most polished prebuilt pack for design-system practitioners.
- **UX / research / handoff:** Owl-Listener's Designer Skills Collection on GitHub (63 design skills + 27 commands covering research, systems, strategy, UI, interaction, prototyping, design ops; MIT-licensed). Install with `/plugin marketplace add Owl-Listener/designer-skills`.
- **Accessibility:** AccessLint (4 dedicated a11y skills + reviewer agent + bundled MCP for color contrast).
- **Brand:** Build your own `brand-guidelines` skill mirroring Anthropic's pattern at github.com/anthropics/skills/blob/main/skills/brand-guidelines/SKILL.md ("Applies Anthropic's official brand colors and typography to any sort of artifact that may benefit from having Anthropic's look-and-feel"), populated with Auterion typography, color, voice, and "do not draw" rules.
- **Design-to-Figma slash command:** Adopt Brian Lovin's `/figma` pattern from the Notion AI team. Per ChatPRD's recap of Lenny Rachitsky's "How I AI" interview: "He simply types /figma in his terminal and pastes the public link to a Figma frame… The command doesn't just do a one-time conversion. It initiates a verification loop: Extract: It uses a Model-Code-Program (MCP) to connect to the Figma API and extract design tokens, layout information, and assets. Implement: It writes the Next.js and Tailwind code to build the UI. Verify: It then uses another MCP—the Chrome DevTools MCP—to open the generated prototype in a browser, inspect it, and compare it visually to the original Figma design… Brian instructed it to loop until the implementation is correct or after three iterations with no changes." Brian also published an `icon-search` Claude Skill that handles a specific failure mode (Claude hallucinating icon names like "search" instead of "magnifying glass").

**Layer 3 — Specialized design tools (each owns one job):**
- **Pencil (pencil.dev):** Real-code design canvas embedded in IDE; 6-agent swarm for divergent exploration; `.pen` files version-controlled in Git alongside code. Best Claude model: Claude 4.6 (per Tom Krcha / Creator Economy interview with Pencil CEO).
- **Magic Path (magicpath.ai):** Infinite canvas with three entry points — text-to-UI, Figma variable import, live web capture. Per UX Tools: "you can import your Figma variables or pick from prebuilt design systems… so everything inherits your tokens." Use for ideation and stakeholder demos; export to React when needed.
- **Figma (and Figma Make / Figma Sites):** Source of truth for the design system, components, variables, and handoff. Figma Make (Config 2025 launch — "an AI-powered prompt-to-code tool that turns written descriptions or existing designs into working prototypes or apps") is your "prompt-to-prototype" for hi-fi flows with your design system applied. Figma Sites (Code Layers launched August 2025; CMS public beta November 20, 2025 per Builder.io) is a Webflow competitor; not recommended over Webflow for marketing yet, but worth tracking. Figma Make custom skills support invocation via slash commands such as `/follow-ds-guidelines` or `/design-crit` (per Figma's help center). Pricing on Figma Make is included in a Full Seat (no separate license needed) but heavy AI use consumes additional credits.
- **Webflow:** Marketing site (auterion.com), AI Assistant for in-product section generation, AI code components for interactive elements (pricing calculators, location finders), Webflow MCP for CMS automation from Claude. Don't use Webflow for product UI.
- **Jira + Atlassian Rovo:** Design intake/triage, PRD generation, ticket grooming, status communication. Build a "Design Intake Triage" agent in Rovo Studio that auto-tags, prioritizes, and clusters incoming requests using your historical pattern data.

**Layer 4 — Code generators (escape valves):** v0 (Vercel/shadcn-anchored, strongest for production React + Tailwind), Lovable (best end-to-end if you need backend/auth/DB and don't have an engineer — Lovable raised $330M Series B in Dec 2025 at $6.6B valuation per TechFundingNews), Bolt.new (fastest prompt-to-preview), Cursor (when you need to drop into the codebase). For a 2-person design team inside a real engineering org, v0 is the right pick — it produces code your engineers will accept; Lovable and Bolt produce code your engineers will replace. Skip Subframe, Galileo AI, and Uizard for production work; they're meaningfully behind the leaders in 2026.

**Orchestration pattern — the "agency week" loop:**
1. **Monday — Intake:** Jira Rovo agent triages weekend stakeholder requests, generates draft PRDs in Confluence, clusters by theme. Human designer reviews and prioritizes in a 30-minute "intake huddle."
2. **Tuesday — Divergence:** Use Pencil swarm mode (6 agents, varied style kits) for any greenfield screen; use Magic Path web-capture for any "make our X look more like Y" stakeholder ask.
3. **Wednesday — Convergence:** Pull selected directions into Figma; apply the design system; run Claude Code with the `/figma` slash command and your design-system-enforcement skills to spec the implementation.
4. **Thursday — Handoff:** Claude Code generates frontend specs, handoff docs, and a developer-ready PR description; engineering picks up via Code Connect mappings.
5. **Friday — Audit:** Run a token-drift audit (Design System Ops skill), an a11y audit (AccessLint), and a Figma library lint (e.g., Design Lint plugin); publish a 1-page status summary auto-generated by Rovo from the week's tickets.

**Human-in-the-loop pattern that works:** Agents propose, humans decide. Specifically — agents draft, designers approve, engineers ship. The biggest failure mode in the field reports (Pencil/Mejba Ahmed; Sen Lin's UX Collective post) is letting the first AI output stand because it "looks polished enough." Build approval gates: never auto-merge an agent-generated PR; never publish a stakeholder-facing artifact without one designer's name on it.

**What fails (be honest):** Multi-agent "auto-pilot" workflows (e.g., agent A briefs agent B who briefs agent C) drift into nonsense within ~15 minutes without human gates. Cross-tool handoffs lose context — every export from Figma to Pencil to code loses something. The roundtrip problem (Builder.io's writeup of Claude Code → Figma → back to code) is real: don't design the workflow as a loop, design it as a one-way pipeline with explicit branch points.

### Section 2 — Brand: world-class identity with two people

**The reference set you should study and pick from, not copy:**
- **Anthropic (designed by Geist):** Per Geist's own case study at geist.co/work/anthropic, the identity uses a "pure typographic logo with a single standout detail. The slash is a reference to the code that underlays AI, and a nod to the future ahead" along with a Styrene + Tiempos pairing and a warm color palette. This is the gold-standard B2B AI identity.
- **Linear:** Geometric monospace logomark, monochrome with one electric accent, IBM Plex Sans / monospace typography pairing. Brand operates on confidence and restraint.
- **Vercel:** Black triangle, Geist font (their own), high-contrast, code-first photography.
- **Stripe:** A bespoke font family (Sohne), gradient and 3D illustration; warm, optimistic.
- **Anduril:** Per Fonts In Use, "Anduril Industries uses Helvetica Now for its website and branding as a metaphor for their position in the defense sector. It respects the old but it builds using modern and new technologies… clear and very minimal with a black and white palette where the only color contribution comes from their products" (plus Chrysler "national safety yellow" accents on the hardware itself, per Fast Company). Tolkien naming, monumental product photography. *This is your closest aesthetic cousin in defense.*
- **Helsing, Palantir:** Disciplined, technical, restrained typography (Palantir is famously cinematic and mythic in its marketing language).
- **Shield AI, Skydio:** More conventional aerospace-defense look — useful as the "do not be this" reference.

**For Auterion specifically:** Your competitive brand position is "the open, software-defined defense autonomy platform" — the Stripe of military autonomy. The brand should look closer to Anthropic/Linear/Vercel (modern, restrained, technical) than to the legacy primes. You already have a credible logomark and a defensible product mythology around Dragon. The two-designer move is to operationalize that, not redesign it.

**The AI agent stack for brand:**
1. **Build a `auterion-brand-guidelines` Claude Skill** modeled exactly on Anthropic's open-source `brand-guidelines` SKILL.md pattern. Encode: typography stack with fallbacks, exact hex palette, voice rules, "do-not-draw" list (no glowing blue HUDs, no clichéd defense imagery, no "AI sparkle" gradients), photography direction, and an accessibility floor (WCAG AA contrast minimums). This file becomes the single source of truth that every other AI tool reads — Claude Design, Magic Path, Webflow AI, Pencil — when generating brand assets.
2. **Branding5's "brand-guidelines.md" pattern:** Maintain a portable, machine-readable Markdown brand file in your repo (or in Claude Projects) that every Claude session loads on first contact. Update it via PR like code.
3. **Adobe Firefly / custom-trained image models:** For brand asset generation (illustrations, hero imagery, social), train a custom Firefly model on your existing brand photography and a curated reference set; never use raw Midjourney / DALL-E output for public-facing brand work. The model itself becomes a brand asset.
4. **Webflow + AI for the site:** Treat auterion.com as the brand's main runtime. Use Webflow's AI Assistant for section generation, AI code components for interactive elements (e.g., a Dragon spec calculator, a fleet ROI calculator), and the Webflow MCP for content updates from Claude.
5. **Pencil/Magic Path for marketing concepts:** Use these for fast hero, social, deck, and landing-page concepts at meeting speed, then refine in Figma + Webflow.

**Brand QA agent (build this):** A Claude Code agent that runs on every PR to the marketing site or any new brand artifact. Its skill includes: WCAG contrast check on every text/background pair, typography validation against the approved stack, color check against the palette JSON, and a "voice check" against your tone rules. This is genuinely doable today with the AccessLint pattern plus a custom voice-check skill.

### Section 3 — Design system: the force multiplier

**The architecture you want (and yes, this is doable with two people):**

```
Figma Variables (Source of truth for designers)
        ↓ Tokens Studio (bidirectional sync)
Git repo (W3C-spec design-tokens, JSON) — single source of truth
        ↓ Style Dictionary (CI/CD transform)
Platform outputs: CSS variables, Tailwind config, iOS/Android, Qt theme files
        ↓
Figma Code Connect CLI (mappings) — ties Figma components to real React/Qt code
        ↓
Figma MCP server + Claude Code skills (consume via AI agents)
```

**Why this works for Auterion specifically:** AMC is Qt/QML-based (it is, per Wikipedia's Auterion entry, "a commercial version based on the open-source QGroundControl project"). Your design system needs to output tokens that work for both web (auterion.com, fleet dashboards) and Qt (AMC). Per the W3C Design Tokens Community Group, the Design Tokens Specification (2025.10) was published on October 28, 2025, with the official announcement stating: "The Design Tokens Community Group today announced the first stable version of the Design Tokens Specification (2025.10), marking a milestone for design systems teams and tool makers worldwide." Style Dictionary can now produce platform-specific outputs (CSS, Tailwind, Swift, Qt CSS) from one JSON source. This is exactly the multi-platform problem Brad Frost calls "Multi-All-The-Things" — and his Subatomic course is the most current reference.

**Concrete stack — pick these:**
- **Figma Variables** with extended collections (Schema 2025 update; multi-mode for light/dark, density, density-by-platform).
- **Tokens Studio** plugin for bidirectional Figma↔Git sync (use this if you want designer-led editing).
- **Style Dictionary v4** for code-side transforms; produces CSS variables, Tailwind config, iOS/Android, and (custom transform) Qt theme files.
- **Figma Code Connect CLI** for component-to-code mappings on your top ~30 components. The CLI version (not the UI version) is what unlocks rich snippets in the Figma MCP responses.
- **Storybook + Chromatic** for the React side; **Qt Quick Designer** + a dedicated `.qml` story file pattern for AMC.
- **Zeroheight** (free tier) for docs; or self-host with the Design System Ops Claude skills if you want AI-native docs.

**Where AI actually helps:**
- **Token audits and drift detection:** Run a weekly Claude Code agent that diffs your Figma variables against your committed tokens.json and flags drift. This is a built-in skill in Design System Ops.
- **Component-code parity audits:** Run Code Connect mappings as the source of truth; an agent reports any Figma component without a CLI mapping or any React component not represented in Figma.
- **Automated documentation:** Use Claude Code skills to auto-generate component docs (props table, usage guidelines, do's/don'ts, accessibility notes) from your TypeScript types and Figma component descriptions.
- **Linting:** Design Lint, Stark, and an agent that reads exported Figma frames before publish and flags non-system colors, off-grid spacing, and orphan components.

**Reference systems to study for a small team:**
- **Shopify Polaris:** Best public token architecture, especially Polaris's primitive → semantic → component layering.
- **Atlassian Design System (ADS):** Best example of design system serving multiple products at once.
- **GitHub Primer:** Best example of component-code parity discipline (every component has Primer React, Primer ViewComponents, and Primer Figma representations).
- **Adobe Spectrum:** Best example of multi-platform tokens; their tokens go to web, iOS, Android, and desktop.
- **Material You:** Best example of dynamic theming.

**The right scope for two designers:** Don't try to be Polaris. Cover 20-30 components really well; document deliberately; ship as a small npm package and a small Figma library; treat Code Connect mappings as the deliverable, not a nice-to-have.

### Section 4 — UX: shipping product with two designers

The most useful frame is the one Brian Lovin uses at Notion: a **shared "Prototype Playground"** repo where every designer has a namespaced folder, every prototype lives in real Next.js + Tailwind code (with your design system applied), and every workflow has a custom Claude Code slash command. This is dramatically more leverage than living in Figma alone, especially for AI-product surfaces where state, latency, and tool calls actually matter. Lovin's guiding rule (from Lenny's Newsletter interview): "Anytime the AI asks you to do something, you should, before responding, try your best to see if you could teach the AI to answer that question for itself."

**Daily UX workflow:**
1. **Design exploration:** Pencil swarm mode for divergent options; Magic Path for stakeholder demos and "import this site, make ours look more intentional than that" tasks.
2. **Mid-fidelity:** Figma with your design system library; use Figma Make for AI-assisted section generation only inside scaffolded files with your variables applied.
3. **Hi-fi prototyping:** Code-based prototypes in the Playground using Claude Code with the `/figma` slash command — turning Figma frames into real Next.js/Tailwind code that engineering can actually pick up.
4. **Critique:** A custom "design critique" Claude skill that reviews a screen against Nielsen heuristics, brand rules, design-system token usage, and a11y. This is in Owl-Listener's collection (`/ui-design:critique`) and is genuinely useful.
5. **User research synthesis:** Notion AI or Claude Projects for interview transcript analysis, pattern extraction, and JTBD synthesis. (For ITAR-touching research, route through Bedrock GovCloud, never through Notion's commercial tier.)

**UX for AMC and Dragon specifically:** Defense/UAV operator UIs have hard constraints: cognitive load, fatigue, color-blind safety, sunlight visibility, glove-friendly hit targets, and high-contrast HUD design. Build a "Tactical UI Rules" Claude skill that encodes these explicitly: minimum 16px text, minimum 44pt touch targets, minimum 7:1 contrast for safety-critical info, mandatory iconography pairs (icon + label), and an explicit "no semantic red except for warnings" rule. Run this skill as a critique pass on every screen.

**The "two designers, hundred stakeholders" problem:** This is a structural ops problem, not a tool problem. The right pattern is the InVision Design Maturity Model's "centralized embedded" hybrid: you operate as a tiny central team with one explicit intake/triage process (Jira + Rovo), one explicit SLA on first response (24 hours), and an explicit decision log (Confluence or a Linear-style "decision" issue type). When stakeholders ask for design work, they go through intake — full stop. The Rovo intake agent + a published decision-log link is your operational moat.

### Section 5 — Design ops with AI

Patrizia Bertini's recent work — including her April 2026 UX Collective piece "Human-Centred Design has grown up. It's time we did too" — emphasizes that DesignOps is "design thinking for operations," not "operations for design teams." Per Roman Schoeneboom's recap of Bertini's April 2025 Rosenfeld DesignOps Summit talk, she puts it sharply: "DesignOps is not operations for design teams — it's design thinking for operations." She also flags the trap that hits small teams hardest: "DesignOps acts like leadership — without the power of leadership. (…) You wouldn't ask a Director of Engineering to book meeting rooms. Why is it acceptable for DesignOps?" — backed by data showing that nearly 45% of individual contributors were expected to carry out strategic work, while 38% of DesignOps leaders were stuck with low-level execution tasks. For a two-designer team, that means:

1. **Capacity dashboard:** A Linear/Jira filter that shows real-time WIP per designer, with an automatic flag if WIP exceeds a documented limit. Rovo can post a weekly capacity summary to your design Slack channel.
2. **Intake/triage automation:** Build a Rovo Studio agent that auto-classifies incoming requests (brand, UX, design-system contribution, "I just need a logo file"), auto-assigns to the right designer, and routes "I just need a logo file" requests to a self-serve brand portal automatically.
3. **Decision log:** Every major design decision gets a Confluence/Notion entry with options considered, decision, rationale, and stakeholders consulted. A Claude Project can generate the draft from Slack thread + Figma file.
4. **Design QA:** Combine the brand-guidelines skill, the design-system-enforcement skill, and AccessLint into one `/design-qa` slash command that any designer can run pre-handoff.
5. **Research repository:** Notion or Dovetail with a Claude skill that semantically searches and synthesizes prior research before any new research starts. (Defense-side: route through Bedrock GovCloud, store in a controlled SharePoint or Confluence Data Center.)
6. **Onboarding:** A self-serve "designer onboarding" Claude Project with your design system, brand skill, voice rules, key tools, and the prototype playground repo loaded as context. New contractors get to productive in days, not weeks.

Dave Malouf (Director of UX Design at Walmart, leading AI/Platform Design/DesignOps) takes the longer view in his Superside interview: "DesignOps is everything that supports the practice of and the value that comes out of designing… In the next two or three years, DesignOps is just everyone catching up. In the next 10 years, DesignOps goes away." With two designers and AI agents, the work distribution should be *agents do execution, designers do judgment*. Track this explicitly; if you're spending more than 20% of your week on agent-doable tasks, the workflow is broken.

### Section 6 — Defense and regulated industry constraints

**The compliance reality as of May 2026:**

1. **Anthropic / DoW supply chain risk designation (Feb 27, 2026):** Federal contractors performing covered DoD work cannot use Claude in any capacity tied to those contracts during the wind-down. Per Hegseth's order: "effective immediately, no contractor, supplier, or partner that does business with the United States military may conduct any commercial activity with Anthropic." Litigation is ongoing — Judge Rita Lin's March 26, 2026 preliminary injunction restored Anthropic access across the 17 named federal agencies — but the practical compliance posture is: do not use Claude.ai consumer or Claude Enterprise for Auterion's covered DoD work. Use Claude through AWS Bedrock GovCloud (FedRAMP High + IL5 + ITAR) for any regulated workloads.
2. **ITAR/EAR:** Per the 2026 ITAR guide (Concentric AI), "shared files, cloud storage access, collaboration tools, and AI prompts can all trigger unauthorized exports of controlled technical data." The cloud Figma file containing your AMC or Dragon UI is the single biggest compliance risk in a modern design stack. Solve this explicitly: any Figma file containing ITAR technical data must be in a Figma Enterprise instance with U.S.-persons-only access and documented access controls.
3. **Three practical architecture patterns** (per Amit Kothari's "running Claude in compliance-heavy environments" writeup):
   - **Pattern A — Commercial (brand, marketing, public surfaces):** Anthropic direct or Claude.ai with ZDR enabled, signed BAA/DPA. Use freely for non-regulated work.
   - **Pattern B — Civilian federal CUI:** Claude for Government (FedRAMP High) or Bedrock GovCloud.
   - **Pattern C — DoD IL4/IL5 + ITAR:** Bedrock GovCloud only. This is the lane for any AMC, Dragon, or anything touching controlled technical data.

**Practical recommendations specific to Auterion:**
1. **Split your AI stack into a "commercial lane" and a "regulated lane,"** with explicit, documented data boundaries and a published one-pager that any designer or contractor can read in two minutes. This is the single most important governance artifact you produce.
2. **Audit your current AI tool stack against FAR 52.204-30** and the DoW designation. Document everything. The "structured analysis is the whole game" advice in the governmentcontractslaw.com piece is correct.
3. **For air-gapped UI design** (for example, anything that genuinely cannot leave a controlled environment), use self-hosted Penpot rather than Figma. Per Penpot's own enterprise comparison: "Because Figma is cloud-only and cannot be deployed in an air-gapped environment, it is not a fit for organizations that require all design work to stay inside isolated or on-premises networks… Self hosting also allows organizations to integrate Penpot with their existing logging, monitoring, and auditing systems to support internal security policies and compliance programs… Penpot is a practical fit because it supports SAML SSO and role-based access control (RBAC)." Penpot supports the same W3C design tokens spec, so your token pipeline works either way.
4. **For the Auterion-side AMC work**, you're partially insulated by the fact that AMC is, per Auterion's Wikipedia entry and its own docs, "a commercial version based on the open-source QGroundControl project" — meaning your design surface for tactical UI is already a Qt design pipeline, not a pure Figma-to-React story. This is a feature: Qt UI design is naturally more constrained and more on-prem-friendly than web design.
5. **Use Microsoft 365 Copilot in GCC-High** (generally available Dec 2, 2025 per the Microsoft Community Hub announcement: "We're excited to announce that Microsoft 365 Copilot is now available for customers in GCC-High," aligned to FedRAMP High, DFARS, ITAR, and CMMC) for productivity work touching CUI — Office, Teams, etc. — and keep your Anthropic relationship for commercial-lane design work via Bedrock GovCloud for regulated.
6. **Anduril operates with Figma + a proprietary "Matter" design system** while doing far more sensitive work than Auterion. This is the proof that modern cloud design tooling is possible inside a defense contractor when the boundary is drawn explicitly.

## Recommendations

**Stage 0 — Foundations (Weeks 1–4). Goal: don't accidentally do something illegal.**
1. **Publish your AI usage policy** — one page, two columns: commercial lane vs regulated lane. Designate which tools (Claude.ai, Claude Code, Pencil, Magic Path, Figma AI, Webflow AI) are approved in each lane. Get sign-off from legal and security in writing. *Benchmark to stop and rewrite this step: your legal team has not yet signed; do not proceed.*
2. **Audit your existing Figma tenant** — confirm Enterprise, confirm SSO, confirm U.S.-persons-only access for any file containing AMC/Dragon UI. Move any non-compliant file to a clean Enterprise instance.
3. **Build the `auterion-brand-guidelines` skill** in the Anthropic format (one Markdown file, encoded as a Claude Skill, also stored as a `brand-guidelines.md` in your design repo). This becomes the source of truth every AI tool reads.

**Stage 1 — Force multipliers (Weeks 4–10). Goal: install the harness.**
4. **Install Figma MCP + Code Connect CLI** for your top 30 components. This is the highest-ROI engineering investment for a design team in 2026. Without it, every AI design tool produces generic output.
5. **Implement the W3C token pipeline:** Figma Variables → Tokens Studio → Git → Style Dictionary → CSS/Tailwind/Qt outputs. Time-box this to four weeks; if it takes longer, you're over-scoping.
6. **Stand up the Prototype Playground repo** (Next.js + Tailwind + your design system). Adopt Brian Lovin's `/figma` Claude Code slash command pattern (Extract → Implement → Verify loop, max 3 iterations).
7. **Install the four-skill design system harness** from Sen Lin's UX Collective writeup (Preflight, Brief Parser, Library-First Construction, Code Mode) or adopt Design System Ops's 21-skill pack wholesale.

**Stage 2 — Operate as an agency (Weeks 10–20). Goal: ship at agency velocity.**
8. **Set up the Jira Rovo intake agent** with a triage scenario for design requests; publish the intake URL to every Slack channel that pings the design team. Measure first-response SLA.
9. **Adopt Pencil + Magic Path** as your divergence + ideation tools; track which screens use which (you'll see a pattern after 4–6 weeks).
10. **Run a weekly "audit Friday"** with three agents: token-drift, accessibility (AccessLint), and brand-QA. Treat the output like CI failures — fix or document.

**Stage 3 — Compound (Month 6+). Goal: build moat.**
11. **Publish your design system externally** (subset of components, no sensitive UI). Becomes a recruiting asset, like Polaris or Primer.
12. **Train a custom Adobe Firefly model** on your brand photography. Every social and marketing asset routes through this model; saves a ton of marketing-design time.
13. **Hire a designer #3** — not "another generalist," but specifically a design technologist who owns the Code Connect mappings, the Style Dictionary pipeline, and the Claude Skills repo. *Benchmark that triggers this hire: you are routinely missing your two-week SLA on intake; your audit Friday is finding more than 10 drift items per week; or your engineering team is asking for design support you cannot provide.*

**Recommendations to skip / postpone:**
- **Don't adopt Lovable or Bolt.new** for production work; the output is too far from your engineering team's standards.
- **Don't switch to Linear from Jira** unless you have leadership air cover and a clean migration window; Atlassian Rovo is good enough.
- **Don't build a custom MCP server** unless you have a clear, unique workflow that no published skill covers. The 1,234+ skills in the Antigravity collection cover most cases.
- **Don't use Claude Design (Anthropic Labs)** for any regulated work; it's a research preview and not in a FedRAMP boundary.
- **Don't try to outsource brand creative to AI image models** for hero/marketing without human direction; the "AI sparkle" tell is real and bad for your brand position vs. Anduril/Anthropic.

## Caveats

1. **Anthropic's DoW status may change** — Judge Rita Lin's March 26, 2026 injunction restored access across all 17 named federal agencies, and Anthropic is litigating the broader designation; the D.C. Circuit, however, denied Anthropic's stay request on the FASCSA designation. Re-check this monthly; if it resolves, you can collapse the "regulated lane" architecture but should keep the documented boundaries.
2. **Figma MCP is still in beta as of May 2026** and is on track to become a paid usage-based feature. Plan for that pricing transition.
3. **Pencil and Magic Path are early-stage startups** and could materially change pricing, fold, or pivot. Treat them as accelerators, not infrastructure. The `.pen` and similar file formats are JSON-based and portable, which limits lock-in risk.
4. **The Anthropic `frontend-design` skill install count of "277,000+ as of March 2026"** is cited in a Medium piece (unicodeveloper) and is not officially published by Anthropic; verify before quoting in any executive comms.
5. **Defense contractor design workflows are under-documented in public.** Anduril, Palantir, Shield AI, and Helsing publish very little about their internal design tooling. The "50 designers at Anduril" figure comes from Mark Wilson's Fast Company piece interviewing Jen Bucci and reflects 2025 numbers; current scale may differ. Palantir designers appear to work in proprietary internal tools (Workshop, Slate, Carbon, Solution Designer, per palantir.com/docs) rather than the Figma-heavy stack most consumer tech designers expect, and the "Matter" design system at Anduril is referenced in job descriptions and not in any public case study.
6. **Several sources in the search results describe future or speculative AI capabilities** in forward tense ("AI agents will…", "future versions will explore…"). Where I've quoted them I've used the verb tense they used; treat narrative claims about 2027+ capabilities with appropriate skepticism.
7. **Headcount and tool-spend math:** A realistic 2-designer agent stack — Claude Code + Claude.ai (Team/Enterprise), Figma Full Seats with Make, Webflow Workspace, Pencil, Magic Path, Jira/Rovo, Notion AI, Tokens Studio, Adobe Creative Cloud — runs in the low five figures per year all-in for two seats. The Code Connect engineering investment is the bigger line item (4–8 weeks of one designer plus part-time engineer help). This is not the place to be cheap; the leverage is real.
